# ADR-0003: MCP Python SDK 2.x targeting spec revision 2026-07-28

Status: Accepted (2026-10-22)

## Context

The spec requires compatibility with MCP revision 2026-07-28 (stateless
Streamable HTTP, `server/discover`). Facts verified against the official
changelog and SDK docs on 2026-10-22:

- Revision 2026-07-28 removes `Mcp-Session-Id` and the `initialize` handshake
  from Streamable HTTP; every request carries protocol version and client
  capabilities in `_meta`. `server/discover` is mandatory. Server-initiated
  requests become multi-round-trip results. Ping, `logging/setLevel`, SSE
  resumability and the HTTP GET stream are removed; roots, sampling and
  logging are deprecated. Dynamic Client Registration is deprecated in favour
  of Client ID Metadata Documents (CIMD).
- `mcp` 2.3.0 implements 2026-07-28 **and serves the previous revision at the
  same time**, so clients still on 2025-11-25 (likely some of Claude, ChatGPT,
  Gemini connectors for a while) keep working.
- In 2.x the server class is `mcp.server.MCPServer`. The 1.x `FastMCP` class
  and the `mcp.server.fastmcp` module no longer exist. Transport options
  (`stateless_http`, `json_response`) moved from the constructor to `run()` /
  `streamable_http_app()`; the 2026 code path has no sessions at all.
- Known SDK gaps: tasks extension, DPoP, `jwt-bearer` grant. Server-side CIMD
  support is not confirmed in the docs - verify before M6.

## Decision

- Depend on `mcp>=2.3,<3`; build the server with `MCPServer`. The spec's
  mention of "FastMCP" is read as "the SDK's high-level server API", which is
  `MCPServer` in 2.x.
- Expose **tools only** (no prompts/resources), all read-only.
- Local development: stdio transport. Cloud: Streamable HTTP mounted in a
  Starlette/FastAPI app, stateless (`json_response=True, stateless_http=True`
  for legacy clients; the 2026 path is stateless by design).
- Auth (M6) uses the SDK's resource-server support: `MCPServer(token_verifier=...,
  auth=AuthSettings(...))`, Protected Resource Metadata served at
  `/.well-known/oauth-protected-resource/mcp` (RFC 9728).

## Consequences

- Hosting (M2/M4): the host ASGI lifespan must enter
  `mcp.session_manager.run()`, and `TransportSecuritySettings` must allow the
  public hostname (default is localhost-only DNS-rebinding protection).
- Request bodies are capped at 4 MiB by the SDK - fine for our tool inputs.
- Re-check the SDK changelog at each milestone; the 2026 revision is young and
  minor releases may change APIs. Pin minor versions in `uv.lock`, not in
  `pyproject.toml`.
- stdio mode: nothing may write to stdout except the protocol (ruff rule `T20`
  bans `print`); logs go to stderr.
